# 매출 계산 및 가입 준비 화면 보완 — 2026-10-02

## 변경
- 총매출은 기존 할인 전 total_sales 의미를 유지한다.
- 실매출 = 총매출 - 할인 - 반품. 반품 초과로 음수가 되어도 숨기지 않는다.
- 비용비율 분모는 총매출이다. 0매출 비율은 미집계로 표시한다.
- 홈 매장 요약, 대시보드 집계, 월말리포트, Excel은 summarizeSalesFigures를 공유한다.
- 월말 예상 순수익은 실매출에서 기존 거래처 지출, 인건비, 고정지출을 차감한다.
- 배달 플랫폼 금액은 총매출 포함 여부가 확정되지 않아 별도 표시하고 중복 합산하지 않는다.
- 저장 전에 원래 입력값의 음수, 비정수, 잘못된 문자열과 DB 정수 범위 초과를 거부한다.
- 잘못된 매출 자료는 정상 합계로 표시하지 않고 계산 불가를 안내한다. Excel은 조회 실패나 잘못된 자료가 있으면 내보내지 않는다.
- 가입 준비 화면에 매니 추천 인건비 20~23%, 식자재 40~43% 안내를 추가했다. 사용자 기존 기준은 자동 변경하지 않는다.
- 가입 준비 체크리스트에서 기존 업무를 수정/삭제할 수 있다. 삭제는 확인 후 저장하고, 매장 전환 후 확인은 무효화하며 실패 시 원래 자료를 유지한다.

## 검증
- 수정 전 최신 메인: node --test security/*.test.mjs tests/*.test.mjs — 527개, 통과 518, 건너뜀 9, 실패 0.
- 수정 후 동일 전체 명령 — 543개, 통과 534, 건너뜀 9, 실패 0.
- 신규 16개: 매출 계산/화면/엑셀/저장 검증 12개, 가입 체크리스트 저장/삭제/매장 전환/실패 검증 4개.
- CONTEXT=production BRANCH=main node scripts/build-environment.mjs 성공.
- 기존 테스트 assertion은 유지했다. 공통 함수 의존성만 VM harness에 추가했고 인건비율 소스 검사는 잘못된 매출일 때 계산하지 않는 조건을 포함하도록 갱신했다.
- submitSalesReport 해시 baseline만 실제 승인된 raw 입력 검증/실매출 저장 변경에 맞게 갱신했다. 다른 급여·직원·개인정보 함수 해시는 변경하지 않았다.

## 남은 작업
세후 실제 급여/보험료/원천세/가불 중복방지, 식자재 전용 비율, 휴무일/무급휴무/스케줄 공동 편집/본사 공지, 입사일 누락 안내, 프랜차이즈 손익 및 개인정보 제외, PDF 월마감과 보관은 이 변경에 포함되지 않는다. 기존 인건비는 아직 세전 계산이므로 이를 세후로 완료했다고 표시하지 않는다. 운영 데이터 수정 없음.
