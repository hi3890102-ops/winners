# 급여 30분 단위 계산 및 매장 합산 수정

확인된 근무 1회별 경과시간을 30분 단위로 내림한 후 합산한다. 예: 8시간 29분 → 8시간, 8시간 30분 → 8.5시간. 29분 근무 두 건은 각각 0시간이다. 자정을 넘긴 근무는 출근일에 귀속된다. 원본 출퇴근 기록은 변경하지 않는다.

화면은 시·분을 표시하되 계산에는 서버 원본 초를 보존한다. 09:00:50~09:30:00처럼 실제 30분 미만인 근무를 30분으로 잘못 계산하지 않는다. 급여 상세와 엑셀은 실제 근무시간과 급여 인정시간을 구분한다.

월급 일할 계산, 확정된 실제 세후급여, 가불 처리, 월마감 과거 스냅샷은 유지한다. 입사일·시급 누락 및 미확인 근태는 임의로 채우거나 승인하지 않는다. 세후 공제율을 정수 천분율로 계산해 JavaScript 부동소수점 때문에 0.9% 공제의 반 원 경계에서 발생하던 1원 오차를 없앴다.

전체 매장 화면은 인건비와 지출을 각각 읽을 수 있는 매장 기준으로 합산한다. 지출 조회 실패가 정상 인건비를 제외하지 않는다. 인건비가 미확정이면 부분 합계, 포함 매장 수, 제외 매장과 사유를 표시하고 비율의 분모도 같은 매장 집합을 사용한다.

## 검토와 검증

- 기존 보존 계약 중 요청된 `calcCrewPayFrom`만 변경했다. 나머지 8개 보존 함수 해시는 동일하다. 해당 함수의 기존 해시 `28755500930543945b400459e5e9b8b78c7af0b8340bae3ad8de68e95a08d2e5`, 변경 후 `9ae4ebab1e5926b6b55976f38f0597544c21b95f0c5c59e806c4bc376534ed4f`.
- 새 급여 경계값·합산 표시 테스트 및 실제 PostgreSQL 계산 테스트를 추가했다. 기존 보존 검사를 삭제하거나 완화하지 않았다.
- 전체 테스트: 595개 중 586개 통과, 기존 환경 의존 테스트 9개 건너뜀, 실패 0개. `node --test --test-reporter=tap --test-concurrency=2 security/*.test.mjs tests/*.test.mjs`.
- 엑셀 원본 시간/인정시간 분리 검증 추가 후 급여 테스트 18개 재실행, 전부 통과.
- 기존 저장 자료의 월별 JavaScript/PostgreSQL 계산 대조에서 불일치 0건. 개인정보와 원본 급여 자료는 저장소에 넣지 않는다.
- 스테이징 빌드 및 환경 격리 preflight 통과. 운영 빌드 통과.
- 스테이징 실제 DB의 합성 역할 검증 통과: 근무별 내림·초 경계·자정 넘김·미확인 근태 제외·실제 세후급여 보존·직원 접근 차단. 검증 레코드는 모두 롤백했다.
- CI에서도 `tests/*.test.mjs`를 실행해 신규 급여 및 DB 검증이 빠지지 않도록 했다.

SQL은 내부 `private.net_payroll_totals` 함수 정의만 바꾼다. `search_path=''`와 public/anon/authenticated 직접 실행 차단을 유지한다. 기존 매장·직원·근태·급여 확정·월마감 자료를 수정하는 문장은 없다. 운영 반영 후 실제 기기의 로그인·엑셀/PDF 다운로드 조작은 별도 확인 범위다.
