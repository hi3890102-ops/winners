# 사장님·직원 앱 사용성 검증 — 2026-10-07

기준 소스: `a6b3cca99f7c48a6542c4a1d4a9f73dda90a8d7b` (`hi3890102-ops/winners`). 신규 기능을 추가하지 않고, 실제 앱 HTML과 이벤트 처리에서 재현한 불편과 오류를 수정했다.

## 검증 방법과 범위

- 사장님, 일반 직원, 매니저 역할의 58개 화면 상태를 320·375·430 CSS px에서 열었다. 총 174회 렌더링에서 문서 가로 넘침과 JavaScript 예외를 확인하고, 주요 화면의 수정 전후 스크린샷을 비교했다.
- 실제 `index.html`과 CSS를 로컬 Chromium에 띄우되 인증 초기화와 Supabase SDK만 가상 데이터로 교체했다. 외부 요청은 차단했으며, 실매장 데이터 저장이나 알림 발송은 하지 않았다.
- 버튼 클릭, 중복 클릭, 입력 오류, 저장 실패, 응답 지연 중 매장 변경, 위치 오류, 조회 실패를 포함한 21개 상호작용을 브라우저에서 실행했다.
- 브라우저: Chromium 134 / Playwright 1.51.1. 화면 날짜는 2026-10-07 12:00 한국 시간. 한글 대체 글꼴은 저장소의 NanumGothic을 사용했다. 실기기의 기본 글꼴과 일치한다고 볼 수는 없다.
- 일반 직원에게 허용되지 않는 매출 화면은 직접 상태를 넣은 렌더링 점검에도 포함했다. 정상 직원 메뉴에서는 매출·체크리스트 삭제·초기화가 노출되지 않는 것을 별도로 확인했다. 이는 서버 권한 검증을 대신하지 않는다.

화면 범위: 로그인·가입·복구, 사장님 홈과 여러 매장, 근태·근무표·고정근무·직원·급여, 매출·지출·거래처·월말보고·비용 입력, 체크리스트·예약·공지·설정, 직원과 매니저의 홈·내 근무·업무·내 정보·설정 화면. 데이터 없음과 긴 매장명도 포함했다.

## 다시 실행하기

기존 Node 검사에 새 파일이 포함되어 기존 코드 검증 작업에서도 실행된다.

```sh
npm ci --ignore-scripts
node --test tests/ui-usability-regression.test.mjs
node --test security/*.test.mjs tests/*.test.mjs
```

격리된 UI 검사는 수동 실행 스크립트다. 기존 공개 로그인 화면 검사나 일일 알림 설정을 변경하지 않았다. 실행 시 로컬 HTML에만 가상 SDK와 테스트 진입점을 주입하며 제품 HTML에는 포함하지 않는다.

```sh
npm install --no-save --package-lock=false --ignore-scripts playwright@1.51.1
npx playwright install --with-deps chromium
QA_OUTPUT=/tmp/manee-ui-qa node scripts/ui-qa/scan.mjs
```

한글 글꼴이 없는 환경에서는 `report-assets/NanumGothic-Regular.ttf`를 설치해야 스크린샷을 읽을 수 있다. `QA_ONLY=flows`로 상호작용만, `QA_SCREENS=staff-expenses,manager-expenses`로 지정 화면과 상호작용을 실행할 수 있다. 결과 JSON과 스크린샷은 `QA_OUTPUT`에 저장되며, 페이지 오류·가로 넘침·상호작용 기대 결과 실패 시 종료 코드가 1이 된다.

## 검증 한계와 남은 실기기 확인

이 결과는 운영 계정 로그인이나 실제 데이터베이스와의 전체 연동을 통과했다는 의미가 아니다. 가상 응답을 사용했으므로 서버 지연·동시 접속 성능도 측정하지 않았다. 174개 렌더링은 화면 상태와 폭의 조합 수이며 모든 화면의 모든 조작을 뜻하지 않는다.

다음은 실제 Android·iPhone 및 테스트 계정으로 별도 확인해야 한다.

1. 로그인·복구·직원 연결 승인 후 사장님과 직원 사이의 실제 권한·데이터 반영.
2. 매장 안 출근·퇴근, 위치 권한 거부·복구, GPS 정확도, 화면 잠금 후 복귀.
3. 휴대폰 키보드가 열린 상태의 입력·스크롤, 시스템 글자 확대, 핀치 확대.
4. 카메라·사진 업로드, PDF·Excel 다운로드·열기, 알림 권한과 수신, 설치된 앱의 업데이트 반영.

운영 데이터와 알림을 사용하는 검사는 별도 테스트 계정·매장 범위에서 수행한다. 이 문서만으로 “전체 오류 없음”이나 네이티브 앱 검증 완료를 선언하지 않는다.
