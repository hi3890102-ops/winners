# 월말 비용 확인·보고서 업데이트

매출보고와 비용 입력 시점이 달라도 현재까지의 보고서를 볼 수 있게 하고, 기록된 비용을 다시 입력하지 않고 연결해 월말 확인을 마칠 수 있게 한다.

- PDF: 흰색·세이지 색상, 요약 / 날짜별 지출 / 거래처별 합계. 긴 목록은 자동으로 페이지를 늘린다. 미분류·음수 환입을 포함하며 각 집계는 중복 합산하지 않는다.
- 현재 월 PDF·엑셀은 잠정 보고서로 바로 열 수 있다. 실제 급여와 영업일 보고를 확인하는 기존 마감·정정 버전 조건은 유지한다.
- 전기·수도·가스: 기존 지출·고정비 연결, 새 지출 입력, 해당 없음, 3일 후 알림. 추가 지출을 고정/변동 반복 비용으로 등록하면 다음 달부터 적용한다.
- 푸시: 한국 시각 월말 D-7 / D-3 / 당일 오전 10시. 비용 확인 완료 매장은 제외한다. 로그인된 사장님에게 연결된 구독만 대상으로 하며 직원·해지된 매장 권한은 제외한다. 지연 선택은 해당 월을 유지한다.
- 스케줄 함수는 외부 URL 호출이 불가능하며 스테이징에서는 발송을 차단한다. DB에서 기기·매장·월·날짜별로 전송을 선점해 중복을 막는다. 전송 실패는 금액·구독 비밀값을 로그로 출력하지 않고 상태만 기록한다.
- 9월 일회성 안내는 자동 발송하지 않는다. 9월 영업 기록이 있는 매장에 "누락 비용 확인" 문구로 별도 안내할 수 있다. 기존 미분류 지출은 이미 합계에 들어간다.

## 검증

- 기존 전체 자동 검증 603 통과 / 0 실패 / 기존 선택적 환경 검사 9 skip.
- 보호 대상 매출·급여 등 9개 함수 해시 유지.
- 새 DB 테스트: 매장·역할 접근 차단, 입력 재시도 중복 방지, 연결 시 금액 불변, 음수·미분류, 다음 달 고정비 1회, 변동비 미자동청구, 만료·중복 푸시.
- PDF 실제 생성·텍스트 검사: 22건 3페이지, 250건(긴 비고 포함) 13페이지. 모든 지출 내역 유지. 한글 전체 글꼴을 내장해 부분 글꼴 누락 문제 해결. 3개 기본 페이지를 렌더링해 확인.
- 실제 스테이징 DB에서 가상 사장님·매장으로 비용 저장/재시도/확인 완료/미리보기/고정비 반복 검증 후 전체 ROLLBACK. 기존 stores 31 / crew 42 / attendance 12 / sales 10 / expenses 5 / fixed 2 및 기존 금액 행 해시 불변.
- 스테이징 보안 검사: 신규 ERROR/WARN 없음. 기존 경고는 별도 기존 항목으로 유지.

## 배포와 복구

두 마이그레이션을 순서대로 적용한 뒤 앱을 게시한다. 첫 번째는 새 비용 확인·반복비·알림 테이블과 RPC, 두 번째는 이전 환경의 비고 컬럼 호환과 공과금 반복 확인 중복 방지다. 기존 장부 행을 수정하거나 삭제하지 않는다.

앱 복구 시 직전 배포로 되돌리고 월말 알림 스케줄을 비활성화한다. 추가된 테이블·입력된 내역은 보존한다. 기존 `private.manee_close_month` 정의는 변경 전 별도 기준선에 보존했다. 마이그레이션을 거꾸로 실행해 사용자 데이터를 삭제하지 않는다.
